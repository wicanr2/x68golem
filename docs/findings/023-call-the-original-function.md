# 023 — 對照一條公式，不必把遊戲玩到那個畫面

日期：2026-09-06

## 問題

M5 的驗收條件是「用 `go test` 重跑一斉攻撃的除數對照」。
那一條在 `sangokushi_x68k_cht` 的 `docs/mechanics/40-military.md` 寫成

```
被攻擊者 D 的損失 = sub_65530(D, A)                        ← 與 k 無關
攻擊者   A 的損失 = sub_65530(A, D) × 地形倍率 ÷ (2k − 1)
```

而它原本是靠 MAME 上的戰場實測定下來的（`docs/playtest/06` §35／§38／§39）：
每驗一次要開新遊戲、跑三個月、進戰場、出陣、佈陣、選一斉攻撃、選方向，
再從記憶體 dump 反推。**驗一次的成本是一場仗。**

## 做法：直接呼叫原版的那支函式

`Machine.CallSubroutine`（`internal/x68k/call.go`）依 XC 的 C 慣例把參數推上
堆疊、推一個哨兵返回位址（`0x1F0030`）、跳進去，跑到 `rts` 回到哨兵為止。
回來時**先檢查堆疊平不平**——差一個 long 就表示參數個數或慣例給錯了，
那種錯會安靜地把之後的執行全部帶歪，所以在那裡就停。

有了它，對照一條公式變成：

1. 在沒人用的記憶體（`0x1E0000`）擺兩個合成的單位槽與武將記錄。
2. 把被攻擊者腳下的地形設成想要的那一種。
3. `ForceRand` 把 `rand(500)` 固定成 400。
4. 攔掉與公式無關的兩支（`sub_62D16` 攻擊演出、`sub_632B0` 重繪單位）。
5. 從同一個快照出發，對 k = 1..6 各叫一次 `sub_655B6(A, D, k)`，看兵數少了多少。

## 結果

```
k=1 除數  1：攻擊者 −780、被攻擊者 −20
k=2 除數  3：攻擊者 −260、被攻擊者 −20
k=3 除數  5：攻擊者 −156、被攻擊者 −20
k=4 除數  7：攻擊者 −111、被攻擊者 −20
k=5 除數  9：攻擊者  −86、被攻擊者 −20
k=6 除數 11：攻擊者  −70、被攻擊者 −20
```

六個除數全部等於 `2k − 1`，而被攻擊者的損失**完全不隨 k 變**——
`docs/mechanics/40` 說的兩件事都成立。

順帶把地形倍率表也跑過一遍：`0x7757A` = `[1, 2, 1, 1, 4, 0]`，
索引是 `(cell & 0x3F) >> 3`。站在城（類型 4）上的敵人打起來自己損失 ×4，
站在山（類型 5）上 ×0——執行結果與表相同。

`TestAttackLossFormula` 是正對照：`−780`／`−20` 這兩個數字本身也是問出來的
（直接叫 `sub_65530` 與 `sub_654F8`），不是拿來當假設。

## 成本

**0.55 秒，而且只要 `SANMAIN.Z` 一個檔案**——不用磁碟、不用 CGROM、不用開機。

`.Z` 是固定位址的平坦映像，公式要讀的倍率表在 data 段裡，載入當下就是對的
（檔案裡 `0x7757A` 就是 `00000001 00000002 00000001 00000001 00000004 00000000`）。
所以連遊戲都不必跑起來。

## 這一份要留下來的規則

**「要驗這條規則，得先玩到那個畫面」是一個可以拆掉的前提。**
無頭執行器與模擬器的差別不在快，在於**可以問問題**：
同一組輸入餵給原版的那支函式，它回什麼。

拆得掉的條件有兩個，缺一不可：

- **位址是確定的**（`.Z` 固定位址，IDA 的位址就是執行期位址）；
- **不想跑的部分可以攔掉**（繪圖、音效、演出各自需要一整套沒擺過的盤面）。

第二點是重點：不攔就得把整個戰場建起來，那又回到「先玩到那裡」。
`Intercept` 讓「只跑要對照的那一段」變成可能，而**攔了什麼要寫下來**——
被攔掉的那幾支就是這條結論沒有涵蓋的範圍。
