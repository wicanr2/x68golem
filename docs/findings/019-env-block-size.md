# 019 — 堆積差的那 512 bytes，是**環境區塊的長度**

日期：2026-09-06

`docs/findings/017` 追到「我們的記憶體版面與真機差一個常數」，
`018` 排除了程式管理區塊的 `+0x30`／`+0x34`／`+0x08` 三個欄位。
這一份把那個常數量出來，並找到它的來源。

## 1. 常數是 +0x200，而且兩份資料一致

MAME 沒有檔案 I/O 的攔截點，所以改用**內容比對**：從我們讀進去的
`MMAPGRP`／`SMAPGRP` 各取 offset `0x4000` 的 16 bytes（先驗過在自己檔案裡
唯一、且不出現在另一個檔案裡），拿去真機的 `0x080000`–`0x100000` 掃描。

```
SMAPGRP+0x4000  FE1A236B2323FE02FE026D7171717100 → 命中 1 次 0x0B4C4E
MMAPGRP+0x4000  80FE280000FE2A00FE02FFFFFE0C00FF → 命中 1 次 0x0A935A
```

| 檔案 | 真機 `+0x4000` | 我們 `+0x4000` | 差 |
|---|---|---|---|
| `SMAPGRP` | `0x0B4C4E` | `0x0B4A4E` | **+0x200** |
| `MMAPGRP` | `0x0A935A` | `0x0A915A` | **+0x200** |

兩份差同一個值 ⇒ 是**配置器的起點**差 512 bytes，不是個別檔案讀錯位置。

## 2. 來源：crt0 把環境區塊的長度加進堆積游標

`SANMAIN.Z` 的 crt0 在 `0x06E720` 開始算配置器的游標 `d1`（起點是 A1 ＝
程式映像結束），逐段累加。其中一段直接讀 A3 指到的環境區塊：

```
0x06E762  2079 0008A9EA   movea.l ($8A9EA).l,a0   ← 開機時存起來的 A3
0x06E768  2010            move.l  (a0),d0         ← 環境區塊開頭的 long
0x06E76A  5A80            addq.l  #5,d0
0x06E76C  0280 00FFFFFE   andi.l  #$FFFFFE,d0
0x06E772  D280            add.l   d0,d1           ← 累加進游標
0x06E774  23C1 0008A9EE   move.l  d1,($8A9EE).l
```

**環境區塊開頭那個 long 是「配置的總長度」，不是「已用的長度」。**
真機上量到的是 `0x200`（在 MAME 把 A3 指向的內容印出來：
指標 `0x049CD0`，開頭 long `0x00000200`，後面全是 0——環境是空的，
但空間照樣配了 512 bytes）。

我們原本只在管理區塊的空隙裡放一個 `0` byte 當環境，那個 long 讀出來是 0：

| | 環境長度 long | `(len+5) & ~1` |
|---|---|---|
| 真機 | `0x200` | `0x204` |
| 我們（修正前）| `0` | `0x4` |

差 **`0x200`**，與量到的常數完全相同。

接在後面的迴圈（`0x06E77A`–`0x06E79E`）另外走過環境**字串**直到連續兩個
null，兩邊都是空的，所以那一段不貢獻差值。

## 3. 修法

`internal/human68k/process.go` 的 `Process` 多兩個欄位 `EnvAddr`／`EnvSize`，
`Layout` 配一塊真正 `DefaultEnvSize`（`0x200`）的區塊，開頭寫進長度：

```go
const DefaultEnvSize = 0x200
...
binary.BigEndian.PutUint32(ram[env:], size)
```

預設放在管理區塊下面（`BlockAddr - size`），與真機一樣位於程式映像之外。

## 4. 這一份要留下來的規則

**交棒契約裡「我們沒用到的欄位」不等於「可以留白的欄位」。**
`docs/findings/002` 當時寫「A3 環境，存起來，這一段還沒用到」——
那句話對的是 crt0 的前 20 道指令，不是整支 crt0。少給一個長度欄位，
代價是之後每一份載入的資料都落在錯的位址，而症狀出現在
**兩百多萬道指令之後的畫地圖迴圈**，中間沒有任何一步會失敗。

排查順序也值得記：先量常數（兩份資料差同一個值），再找誰產生那個常數。
反過來從「畫地圖迴圈讀到 0」往回猜，`017`／`018` 猜錯了兩次。

## 5. 驗證

改完之後重跑同一段按鍵序列，`_READ` 的緩衝區位址是：

```
MMAPGRP → 0x0A535A     SMAPGRP → 0x0B0C4E
```

減去 `0x4000` 之後正是真機的簽章命中位址（`0x0A935A`／`0x0B4C4E`）。
再把記憶體整段印出來對照，`0x0BBC00` 與 `0x0E0000` 兩段的前 64 bytes
與 MAME 的 dump **逐位元組相同**。記憶體版面的落差到此結束。
