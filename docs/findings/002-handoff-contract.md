# 002 — Human68k 交棒契約：從 crt0 反推

日期：2026-09-06　輸入：`SANMAIN.Z`（sha256 `8d164deb…`，玩家自備）

一開始我們把暫存器清 0 就跳進進入點，走 82 道指令。補上這一份契約之後
走到 2,345 道，再接上 `_SETBLOCK`／`_INTVCS` 與 CRTC 的動作位元之後，
`-lenient` 下已經跑到兩千萬道指令還沒停。

## 證據：crt0 讀了哪幾個欄位

用 `cmd/probe -trace` 取得（指令字與延伸字都留，因為重點常在延伸字裡）：

```
0x04FFFA  4EF9 0006 E6D6   jmp    $6E6D6
0x06E6D6  4FF9 0008 B468   lea    ($8B468).l,sp
0x06E6DC  23CA 0008 A9F6   move.l a2,($8A9F6).l     ← A2 存起來（之後逐 byte 讀）
0x06E6E2  23CB 0008 A9EA   move.l a3,($8A9EA).l     ← A3 存起來
0x06E6EC  4BE8 0100        lea    ($100,a0),a5
0x06E6F6  2028 0034        move.l ($34,a0),d0
0x06E706  2028 0030        move.l ($30,a0),d0
0x06E716  23C9 0008 A9CE   move.l a1,($8A9CE).l     ← A1 存起來
0x06E71C  4BE8 0010        lea    ($10,a0),a5       ← 之後給 _SETBLOCK
0x06E9EE  41E8 0080        lea    ($80,a0),a0       ← null 結尾字串
0x06E9FA  41E8 00C4        lea    ($C4,a0),a0       ← null 結尾字串
```

## 定下來的（L2）

| 暫存器／欄位 | 是什麼 | 憑什麼 |
|---|---|---|
| **A0** | 記憶體管理標頭 | `lea ($10,a0),a5` 之後 a5 就是 `_SETBLOCK` 的區塊位址；`lea ($100,a0),a5` 則對到程式映像本身 ⇒ **A0 ＝ 載入基底 − 0x100** |
| A0+0x80 | 執行檔路徑（null 結尾）| `lea ($80,a0),a0` 之後是 `move.b (a0)+,(a2)+` / `bne` 的複製迴圈 |
| A0+0xC4 | 執行檔檔名（null 結尾）| 同上 |
| **A1** | **程式映像的結束**（bss 之後）| crt0 以 A1 為起點逐段加上對齊過的大小，最後 `sub.l a5,d1` 得到要保留的長度 |
| A2 | 命令列 | 存起來之後 `move.b (a0)+,d1` 逐 byte 解析 |
| A3 | 環境 | 存起來，這一段還沒用到 |

## A1 給錯的那一次，是自己露出來的

第一版把 A1 給成「記憶體的結束」，crt0 算出來要保留 **0x220D08**（2.2 MB）
——比整台機器的記憶體還大。改成 bss 結束之後是 **0xAC97C**（約 690 KB），
程式本體 0x3B87A 加上堆積與堆疊，量級對得上。

**這是自檢，不是猜對了**：`_SETBLOCK` 的長度參數是由被測程式自己算出來的，
所以它會替我們檢查交棒契約給得對不對。

## 還沒有證據的（L3）

- A0+0x30、A0+0x34 這兩個 long 的意義。crt0 只是把它們搬到別處存起來，
  目前給的是區塊結束位址。錯了會在用到它們的地方露出來。
- `_INTVCS` 回傳的「舊向量位址」我們一律回 0；真機上會是 Human68k 自己的
  處理常式。程式若把它存起來稍後還原，還原成 0 會出事。
