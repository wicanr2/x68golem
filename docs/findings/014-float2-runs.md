# 014 — `FLOAT2.X` 跑起來了：亂數直通模式成立

日期：2026-09-06

`docs/spec/005` §4 原本寫著「**沒有直通模式**」，理由是
`FLOAT2.X` 的 `rand()` 演算法還沒解出來，而任何「大概對」的亂數都會產生
自洽但錯的對拍結論。

**現在有了——但不是因為解出了演算法，是因為把那支程式載進來跑。**

## 怎麼做的

`FLOAT2.X` 是 Human68k 的 `.X`（可重定位執行檔）。檔頭 64 bytes 對得上：

```
'HU' 基底 0 進入點 0x138 text 12160 data 0 bss 0 reloc 542 symbol 0
64 + 12160 + 0 + 542 + 0 = 12766 ＝ 檔案長度
```

重定位表的編碼取自 [`erique/ghidra-human68k`](https://github.com/erique/ghidra-human68k)
的 `Human68kRelocation`：讀一個 word，0 結束、1 表示後面接 32-bit 位移、
奇數表示補一個 word（位移是 d−1）、其餘補一個 long。位移**累加**。

自我檢查：542 bytes 的表全部是 word 項目，套出 **271** 個重定位
（542 ÷ 2 = 271，一個不多一個不少）。

載到 `0x20000`、套上重定位、照一般程式的交棒契約跑進去，它：

1. 用 `$84 _B_LPEEK` 讀向量表（peek／poke 家族因此要實作）；
2. 用 `$FF09 _PRINT` 印招牌
   ——「浮動小数点演算パッケージエミュレータ for X68000 version 1.00
   （IEEEフォーマット）」；
3. 把 **F-line 向量從我們的樁 `0x1F0000` 換成它自己的 `0x02006A`**；
4. `_KEEPPR` 常駐。

之後 `$FE0E`（`rand`）走的是**真的程式碼**。Human68k 的 DOS call
（`$FF00–$FF7F`）它不處理，會鏈回舊向量——那正是我們的樁，所以兩邊都通。

## 證據：能力值不再是同一個偏移

`-rand-fixed 12345` 時五項全是「基本値 − 2」（`docs/findings/010`）。
換成直通之後同一個畫面是

```
身体（基本値 88）  -- 84 --
知力（基本値 93）  -- 89 --
武力（基本値 94）  -- 95 --
```

各自不同的偏移——**那是真的亂數在動**。

一路跑到 189 年 2 月，金利 147、米相場 37（固定亂數那次是 105／108）。

## 一個 `_PRINT` 的坑

Human68k 的 `_PRINT` 是 **NUL 結尾**，不是 MS-DOS 那個 `$`。
照 MS-DOS 的習慣找 `$` 的話，招牌後面的整段程式碼都會被當成字串印出來
——那一段輸出本身就是證據。

## 動畫畫面不會「靜下來」

能力值抽取那一頁的數字會一直跳（原版就是這樣），所以
「等畫面靜下來」的同步在那裡永遠不成立。`cmd/play -busy-ok` 讓它照樣送鍵。
**這不是模擬的問題，是那一頁本來就在動**——分清楚這兩者很重要。
