# 007 — 卡在 PCM：DMAC 的連續模式還沒做

日期：2026-09-06

主迴圈跑起來之後，`-hot` 指出它把 89% 的時間花在三行上：

```
0x06A678  tst.l ($795D4).l
0x06A67E  beq.s -8              ← 等旗標變非 0
0x06A680  jsr   $711A4          ← 讀 ($711A2)
0x06A688  bne.s -10             ← 等它變 0
```

`-hot` 這支就是為了回答「它卡在哪」——不用讀碼猜，執行次數自己會說。

## 追到底

`($711A2)` 是 PCM 的忙碌旗標：

```
0x0710F8  move.b #2,($E92001)      ← ADPCM 開始
0x071100  move.b #1,($711A2)       ← 忙碌 = 1
```

清掉它的是 DMA 完成中斷的處理常式：

```
0x071150  movem.l d0-d1/a1,-(sp)
0x071154  move.b  ($711A0),d0      ← 播放模式
0x07115A  clr.b   ($711A0)
0x071160  btst    #7,d0
0x071164  bne.w   0x071184         ← bit7 ＝ 還要繼續，不要停
0x071168  move.b  #1,($E92001)     ← 停 ADPCM
0x071170  clr.b   ($711A2)         ← 忙碌 = 0
0x071176  movea.l (d16,pc),a1
0x07117C  move.w  #$6A,d1
0x071182  trap    #15              ← _B_INTVCS(0x6A, a1) 重新掛向量
```

向量 **0x6A** 就是 DMAC 通道 3（X68000 上的 ADPCM 通道）的中斷向量。

## 路上修掉的：`_B_INTVCS` 要真的寫進向量表

原本 `_B_INTVCS` 只把位址記在旁邊的 Go map 裡。硬體中斷是照 68000 的
例外向量表跳的——記在旁邊等於沒掛，DMA 完成中斷永遠找不到處理常式。
改成編號 < 0x100 就寫進 `RAM[編號×4]`（0x100 以上是 Human68k 自己的號碼，
沒有對應的硬體向量，才記在表裡）。

改完之後中斷真的進去了：`DMA 完成 1 次`，第一個等待迴圈通過。

## 還卡著的：連續模式

處理常式在 `btst #7,d0` 之後跳走了——播放模式的 bit 7 是「還要繼續」。
真機上 HD63450 走**連續（陣列鏈接）模式**：DMAC 自己接著搬下一塊，
一塊一塊放完才把 bit 7 清掉。我們的 DMAC 只做「開始 → 立刻完成 → 發一次
中斷」，沒有鏈接，所以第二塊永遠不來，忙碌旗標也就永遠不清。

下一步是把 HD63450 的連續模式做出來（讀鏈接表、逐塊完成、每塊發一次中斷）。
**不做的替代方案是「直接把忙碌旗標清掉」——那個不能做**：那是替遊戲決定
它自己的狀態，對拍工具一旦開始這樣做，就沒有東西能保證它跑的還是原版的流程。
