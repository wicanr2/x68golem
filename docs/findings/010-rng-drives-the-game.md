# 010 — 受控亂數直接算得出畫面上的數字

日期：2026-09-06

這一項是這個專案的目的本身：**把亂數變成輸入之後，原版畫面上的數字
可以用公式逐項算出來，不必談樣本數。**

## 畫面

一路按到君主能力值抽取（劇本 1 董卓打倒、選曹操）：

```
身体    （基本値 88）  -- 86 --  PUSH SPACE BAR !!
知力    （基本値 93）  -- 91 --  PUSH SPACE BAR !!
武力    （基本値 94）  -- 92 --  PUSH SPACE BAR !!
カリスマ（基本値100）  -- 98 --  PUSH SPACE BAR !!
運勢    （基本値 97）  -- 95 --  PUSH SPACE BAR !!
```

跑的時候 `rand()` 被固定成 **12345**（`cmd/probe -rand-fixed 12345`）。

## 逐項對

`sangokushi_x68k_cht` 的 `docs/mechanics/05-newgame.md` 記的公式是

```
v = min(100, 表值 + rand(11) − 5)     （0x6b170-0x6b190）
```

而 `sub_60580(n) == rand() % n`（`docs/re/12`）。所以

```
rand(11) = 12345 % 11 = 3        （11 × 1122 = 12342，餘 3）
偏移     = 3 − 5 = −2
```

| 能力 | 表值 | 預測 | 畫面 |
|---|---|---|---|
| 身体 | 88 | 86 | **86** |
| 知力 | 93 | 91 | **91** |
| 武力 | 94 | 92 | **92** |
| カリスマ | 100 | 98 | **98** |
| 運勢 | 97 | 95 | **95** |

五項全中。

## 為什麼這件事重要

沒有受控亂數的時候，要驗這條公式只能跑很多場、看分布，然後談信賴區間
——而分布對不上的時候，分不出「公式錯了」還是「亂數流不一樣」。
把 `rand()` 固定成一個值之後，**預測是一個確定的數字，比對是逐項的**。

同一條路可以用在戰場：`sangokushi_x68k_cht` 為了定出一斉攻撃的分攤除數，
花了八輪去製造包夾局面，最後靠「同一條亂數流、不同常數」的交叉檢定
才分得出 2 和 3。有了 `Fixed`／`Seq`／`Replay`，那種問題變成「餵一組值、
讀一次結果」。

## 這也順帶驗了別的東西

畫面上的基本值（88／93／94／100／97）是從 `SAVEDATA` 讀出來的劇本資料。
它們對得上，表示 FAT12、`_OPEN`／`_READ`、以及劇本記錄的版面都是對的
——**一條鏈上任何一環錯了，這五個數字就不會同時對**。
