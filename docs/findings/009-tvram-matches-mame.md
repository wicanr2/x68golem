# 009 — text VRAM 與 MAME 逐位元組相同（M3 的文字面驗收）

日期：2026-09-06

## 比什麼

不是截圖，是 **VRAM bytes**。截圖會受縮放、色彩修正與擷取時機影響；
記憶體內容不會。MAME 那邊用
`sangokushi_x68k_cht` 的 `tools/x68k-scripts/dump-tvram.lua` 把
`0xE00000` 起的 128 KB（text 平面 0）與 `0xE82200` 的文字調色盤 dump 出來，
我們這邊用 `cmd/probe -dump-tvram`。

兩邊走的是同一條操作序列：開機 → 空白鍵 → Return → `1` → Return。

## 結果

| 畫面 | MAME 非 0 bytes | x68golem 非 0 bytes | 相異 bytes |
|---|---|---|---|
| 標題（`1:NEW GAME 2:LOAD DATA`）| 293 | 309 | **16** |
| 劇本選單（董卓打倒…三国の時代）| 2,881 | 2,897 | **16** |

兩次都是 16 bytes，而且位置完全規則：

```
標題    y=272..287  x=376..383   我們 0xFF，MAME 0x00
劇本    y=400..415  x=368..375   我們 0xFF，MAME 0x00
```

同一個 byte 欄位連續 16 列 —— 那是**游標那個 8×16 的方塊**。
差異是它的**閃爍相位**，不是畫錯。

`TestBootToTitle` 用固定步數再跑一次時，相位剛好對上：

```
boot_test.go:91: 與 MAME 完全相同
```

131,072 bytes 全部相同。

## 測試怎麼寫的

`compareWithMAME` 驗的是「**差異只有游標那一塊**」，不是「完全相同」：
差異必須落在同一個 byte 欄位、連續的列、最多 16 筆。多一個 byte 落在
別的地方就是真的畫錯了，測試會指出座標。

這樣寫的理由：相位差是真實存在的時序差異（我們的垂直同步時間軸是
`docs/spec/002` §4 講的「指令級」近似），**把它斷言成 0 會讓測試在
無關的時序調整下亂閃**；但放寬成「差幾個 byte 都行」又會漏掉真的錯誤。
限定形狀是兩者之間唯一誠實的寫法。

## 這代表什麼

- 68000 核心、Human68k 服務層、FAT12、CGROM 取字模、CRTC、垂直同步、
  DMAC——這一整條路上任何一個環節錯了，畫出來的 bytes 就不會相同。
  **131,072 bytes 相同是一個很難僥倖通過的檢查。**
- 還沒驗的：圖形平面（開場動畫還沒畫到）、調色盤內容、其他三個文字平面。
