# 001 — M0 第一次跑：靜態普查漏了 5 個服務

日期：2026-09-06　工具：`cmd/probe`（commit 見 git log）
輸入：`SANMAIN.Z`（sha256 `8d164deb71042704edd494f5645bd3814b719b82a3fe6c9fcefa547aab096f4e`，玩家自備）

## 嚴格模式：82 道指令

```
執行 82 道指令後停下
停下的原因：DOS call $4A（$FF4A）尚未實作，第一次出現在 PC=0x06E7E0
```

**`$FF4A` 這一個站點不在靜態普查裡。** `sangokushi_x68k_cht` 的
`workplace/ida/x68k/census/doscalls.txt` 把 `0x6E7E0` 列在
「byte 掃描候選：落在資料裡／未探索區」那一組（7 個候選之一），
沒有計入 28 個確認站點——而它是 crt0 進入之後第 82 道指令就會執行到的碼。

這是 `docs/spec/003` 那句「普查是下界不是全部」的第一個實例，
也正是 M0 存在的理由。

## `-lenient`：3,000,000 道指令

沒實作的服務回 D0=0 繼續跑。**這樣得到的清單只是線索**：程式會依回傳值分支，
回 0 等於替它選了一條路，可能少（走錯路沒碰到）也可能多（走進錯誤處理）。

| | 靜態普查有 | 這一輪跑到 |
|---|---|---|
| DOS call | `$06 $1A $20 $23 $3C $3D $3E $3F $40 $42 $44` | `$06 $23 $44` ＋ **`$21` `$25` `$4A`** |
| IOCS | 33 種，含 `$10 $70 $7D $81 $90` | `$10 $70 $7D $81 $90` ＋ **`$0E` `$72`** |

粗體是靜態普查裡沒有的五個。其中 **`$4A` 是嚴格模式下走到的，確定為真**；
其餘四個出現在開始回 0 之後，只能算線索。

執行到 3,000,000 道指令時的狀態：清完 text VRAM 的 65,536 個字
（`0xE00000–0xE1FFFE`，`PC=0x0713B2`），然後卡在
`0xE80481` 的輪詢——讀了 1,431,371 次。那是 CRTC 的光柵／垂直同步暫存器，
我們一直回 0，所以它永遠等不到。**這就是下一件要做的事**（M4 的計時器）。

## 這一輪不能宣稱的事

- 不能說「SANMAIN.Z 只用這 13 個服務」。跑得多遠取決於實作了多少，
  M0 的產出是一個**佇列**，不是一份完整清單。
- 不能說 `$21`／`$25`／`$0E`／`$72` 一定會在正常玩家路徑上出現。
- 硬體面只碰到 CRTC 與 text VRAM，因為還沒走到會用 DMAC／FDC／OPM 的地方。
