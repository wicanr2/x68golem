```

```

再按一次還會走到劇本選單：


## 最後三個關卡，每一個都很小

### 1. 沒有 CGROM，字就是空白

前一輪跑滿六千萬道指令、text 平面卻一個非 0 像素都沒有——因為
`0xF00000` 一直回 0。掛上使用者自備的 `cgrom.dat` 之後，同一次執行
立刻出現 **410 個非 0 像素**，內容是

```
スペースキーを押して下さい。
```

**CGROM 不內嵌、只掛使用者自備的**（`docs/spec/001`）——那是 Sharp 的。

### 2. Return 是 CR（0x0D），不是 LF

第二個畫面是

```
乱数の初期化中です。
少し待ってからリターンキーを押して下さい。
```

送 `0x0A` 沒有反應，送 `0x0D` 才過。`-keys` 現在把 `\n` 與 `\r` 都對到 CR。

### 3. 按鍵之間要隔時間——**因為遊戲拿等待時間當亂數種子**

那個畫面明講「少し待ってから」（等一下再按）。一次把整串鍵倒進佇列
等於零延遲，種子就固定了。`Keyboard.Delay` 因此存在，預設 20,000,000 週期
（10 MHz 下約 2 秒）。

這一條與 `docs/findings/005` 互相印證：`srand` 的種子確實來自玩家的行為，
而 `rand()` 在 `FLOAT2.X` 裡。開機時看到的兩次 `srand(1308)`／`srand(61)`
是程式自己給的初值，真正的種子在這個畫面決定。

## 回歸測試

`TestBootToTitle`（`internal/x68k/boot_test.go`）把這條路釘住：需要玩家自備
的執行檔、磁碟與 CGROM，缺一樣就 skip。斷言的是兩個數字——走過的相異位址
> 3,500、文字平面的非 0 像素 > 500——**刻意留寬**：它要抓的是「又壞回去了」，
逐像素的對照 oracle 是 MAME（`docs/spec/003`），那是 M3 的事。
